# TaskBridge Release Management

TaskBridge releases are produced from semver Git tags with GoReleaser. The release path publishes GitHub Release assets, checksums, SBOMs, direct Linux package files, a Homebrew cask, and a Scoop manifest. Snapshot releases are rehearsal-only and must not update package-manager repositories.

## Version Source

The single runtime version source is `pkg/buildinfo`:

- `Version`
- `GitCommit`
- `BuildDate`

Local builds and GoReleaser releases must inject those values with `-ldflags` so `taskbridge --version`, archive metadata, and release assets describe the same build. The Taskfile and release configuration are the maintained entry points for those flags; do not hand-edit version strings in documentation or command output for a release.

## Release Prerequisites

Before cutting a release, confirm:

- Go 1.25 or newer is installed.
- `task` is installed and can run project tasks.
- GoReleaser is installed for local checks.
- The working tree is clean and the intended release commit is pushed.
- The release workflow can use the repository-scoped `GITHUB_TOKEN` for GitHub Release assets.
- Cross-repository package publishing has `PUBLISHER_TOKEN` available. The preferred source is a short-lived token minted by `actions/create-github-app-token@v3` for `yeisme/homebrew-tap` and `yeisme/scoop-bucket`; a personal access token is an operator exception, not the default design.

## Validation Commands

Run the release gate from the repository root before tagging:

```bash
task test
task test:integration
task build
task release:check
task release:local
```

`task release:local` is a snapshot rehearsal. It builds release artifacts locally with publishing disabled, so it must not update Homebrew or Scoop.

## Semver Tag Flow

TaskBridge releases use tags in the form `vX.Y.Z`.

1. Choose the next semver version.
2. Run the validation commands above.
3. Create and push the release tag:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

Pushing the tag starts the release workflow. The workflow publishes GitHub Release assets with `${{ secrets.GITHUB_TOKEN }}` and passes `PUBLISHER_TOKEN` only to the package-index publishing steps.

## Snapshot Flow

Use snapshots when validating release packaging before a public tag:

```bash
task release:local
```

Snapshots build local artifacts and run without publishing. They are allowed to create files under `dist/`, but they must not push Homebrew cask updates or Scoop manifest updates.

## Published Artifacts

A tag release publishes:

- Platform archives for Linux, macOS, and Windows on supported architectures.
- Windows archives as `.zip`; other platform archives as `.tar.gz`.
- Archive names containing project, version, title-cased OS, and normalized architecture.
- `checksums.txt` with sha256 checksums.
- SPDX JSON SBOMs for archive artifacts.
- Direct `.deb`, `.rpm`, and `.apk` assets generated by nFPM.
- Homebrew cask metadata in `yeisme/homebrew-tap/Casks/taskbridge.rb`.
- Scoop metadata in `yeisme/scoop-bucket/bucket/taskbridge.json`.

The nFPM files are direct GitHub Release assets. They are not repository-backed APT, YUM, or APK channels.

## Post-Release Smoke

Validate installed artifacts with commands that do not require provider credentials:

```bash
taskbridge --version
taskbridge --help
taskbridge demo today
```

Package installers must install only the `taskbridge` binary and static metadata. They must not create provider credentials, OAuth tokens, local task stores, or remote Todo writes. After installation, users should run:

```bash
taskbridge doctor
taskbridge quickstart
taskbridge auth status
```

Provider-specific login remains explicit through commands such as `taskbridge auth login microsoft` or `taskbridge auth login todoist`.

## Rollback

Prefer forward fixes over rewriting public release history.

1. If a release fails before users can install it, stop the workflow, remove any partial GitHub Release draft, fix the issue, and rerun from a clean tag.
2. If a release is public and broken, publish a new patch version with the fix.
3. If Homebrew or Scoop metadata points to a bad artifact, revert the generated tap or bucket commit and publish a corrected patch release.
4. If a GitHub Release asset is unsafe to keep available, remove that asset from the release and document the replacement version in the release notes.

Do not reuse a public semver tag for different bits after package indexes or users may have cached it.
